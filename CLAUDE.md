# Slides Plugin

One skill, `slides`, that takes someone from an idea and some notes to a finished, on-brand PowerPoint deck.

## Design philosophy

Changes should preserve these:

- **The thinking is the person's.** Who it's for, whether it's presented or read, and what the audience should think, feel and do come from the grill, in their words. The skill doesn't work these out for them.
- **The story is approved before anything is built.** A person can judge a story by reading its headers, and it is cheap to fix as a list.
- **Approved headers survive the build word for word.** If one won't fit, the skill asks.
- **Brand is the only rule on looks.** Fonts and colours are captured once and checked by `scripts/brand.py`. Layout belongs to Anthropic's `pptx` skill, and this skill has no other opinion on it.
- **Stay small.** Up to v0.21.0 this was six skills, about 25,000 words of instructions and 23 scripts, and it is all still at that tag. Add something back only when real use has shown the need.

## Structure

### Source (single source of truth)

- `source/skills/` - skill source files. Edit here, not in the generated output directories.
- `source/commands/` - the OpenCode slash-command wrapper. Edit here.

### Generated output (committed, do not edit directly)

- `.claude/skills/` - Claude Code output. Identity transform; source is emitted as-is.
- `.opencode/skills/` - OpenCode output. Claude-only fields stripped, `$ARGUMENTS` and `/slides:` references rewritten.
- `.opencode/commands/` - OpenCode slash command: a thin `@.opencode/skills/slides/SKILL.md` include, invoked as `/slides`.
- `.agents/skills/` - Codex output for repo-local discovery.
- `plugins/slides/skills/` - Codex output for Plugins UI install packaging. Byte-identical to `.agents/skills/` (enforced by a 3-way sandbox test in `builder.test.js`).
- `.codex/skills/` - Codex cross-harness bridge. Byte-identical to `.agents/skills/` via shared `codexRewrites` by reference. Exists so tools that cross-read `.codex/skills/` (notably Cursor) can discover the skill.

### Static manifests (hand-authored, committed)

- `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` - Claude Code plugin descriptors.
- `plugins/slides/.codex-plugin/plugin.json` - Codex plugin manifest.
- `.agents/plugins/marketplace.json` - Codex marketplace catalog pointing at `./plugins/slides`.

These four JSON files are NOT regenerated by `npm run build`. Edit them by hand; version bumps must be applied across all four version carriers together (see "Versioning" below).

## Conventions

- A skill has a SKILL.md with frontmatter (name, description, and, for user-invocable skills, user-invocable and argument-hint).
- Scripts go in a `scripts/` folder beside the SKILL.md that uses them.
- Anthropic's `pptx` skill is proprietary. Call it; never copy or paraphrase its content into this repo.
- The skill must work standalone in every harness, or say plainly when it can't.

## Build pipeline

```
npm run build                        # regenerate all output directories from source/skills/
npm run check-sync                   # verify version parity + outputs match what is committed
npm test                             # transformer, builder, manifest, skill-contract and check-sync tests
python3 -m unittest discover tests   # the brand script and the release docs
```

Transformer scripts live in `scripts/`. Harness capability details and transform rules are in `HARNESSES.md`.

### Pre-push checklist

All three gates must pass before push. `npm run check-sync` catches drift in the generated outputs and across the four version carriers in `scripts/transformers/version-carriers.js`. It compares against git, so commit first. `npm test` cross-checks version parity in-process and verifies the drift detection itself. `python3 -m unittest discover tests` needs python-pptx. CI (`.github/workflows/ci.yml`) runs the same three gates on push and PR to main.

## Versioning

Version lives in four files that MUST be bumped together:

- `.claude-plugin/plugin.json` (Claude Code plugin)
- `.claude-plugin/marketplace.json` (Claude Code marketplace, `plugins[0].version`)
- `plugins/slides/.codex-plugin/plugin.json` (Codex plugin)
- `package.json` (build pipeline)

The canonical list lives in `scripts/transformers/version-carriers.js`. `npm run check-sync` fails if any of the four disagree. `manifests.test.js` enforces the same parity in-process.

## Testing

After any source change, run `npm run build` before committing.

### Testing caveats (accepted risks)

One known risk in the current test suite, judged acceptable for this single-maintainer repo:

- **`check-sync.test.js` mutates a committed file.** The test writes `"99.99.99"` into `plugins/slides/.codex-plugin/plugin.json`, spawns `check-sync.js` synchronously, and restores in a `try/finally`. If Node dies between the write and the restore (vanishingly unlikely, because `spawnSync` is synchronous), the working tree is dirty. Recovery: `git checkout -- plugins/slides/.codex-plugin/plugin.json`. Concurrency with other writers to the same file is avoided by `--test-concurrency=1` in the `test` script; do not remove that flag without redesigning the test to sandbox the file.
